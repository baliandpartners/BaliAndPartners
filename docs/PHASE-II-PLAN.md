# Phase II implementation plan — 30 October 2026

## Current audit

The live React/Vite application is deployed by Vercel from `project`, with prerendered routes and a private Supabase enquiry/callback API. Founder imagery, all 24 service disclosures, navigation, article search/category filters, related articles, publication validation and a three-stage fictional editorial specimen already exist. The new motion release adds header Contact access, fine-pointer feedback, layered artwork, finite reveals, page transitions, progress and an accessible visitor preference. It has passed 83 local browser checks and a local mobile Lighthouse run (performance 97, accessibility and best practices 100).

The remaining gaps are guided commissioning, structured briefs, multiple editorial demonstration subjects, a routine publishing workflow outside source-code edits, aggregate engagement/performance measurement, and a documented private-client-portal architecture.

## Prioritised stages

1. **Publish and verify the motion/navigation release.** Preserve native links, selection, Back/Forward, touch navigation, reduced-motion behaviour, general enquiries and callbacks. Release only after hosted checks. Keep the previous main commit as rollback.
2. **Guided service discovery and project briefs.** Add an accessible discovery journey and contextual service/recurring-support links. Carry only non-personal, validated commissioning choices into Contact. Extend the private enquiry schema and API with bounded project-brief fields; preserve general and callback requests. Add explicit validation, receipts and actual hosted database acceptance tests. No prices, outcome guarantees or confidential document uploads.
3. **Editorial demonstrations and publishing foundation.** Expand the existing specimen rather than creating a duplicate. Clearly mark all demonstrations fictional. Extend the existing approved-publication architecture with private Supabase editorial records, review/rights controls and a documented authorised-dashboard-to-production publishing workflow. Preserve useful article metadata, dates, filtering, search, related links and sitemap generation; never publish invented client work or legal authorities.
4. **Privacy-conscious measurement and administration.** Use first-party aggregate engagement and performance measurement with bounded event schemas, no enquiry contents, no advertising identifiers and browser privacy preference support. Keep enquiry management and content authorisation in the private Supabase administrator environment. Verify RLS and ensure public bundles contain no privileged keys.
5. **Client portal proposal and release handoff.** Describe invitation-only authentication, tenant isolation, private storage, milestones, reviews and approvals, migration/security testing and a phased delivery plan. Do not deploy a demonstration portal. Validate completed features on mobile/desktop and production, then report limitations and Phase III priorities precisely.

## Release discipline

Use coherent feature branches, tested previews and exact-commit merges. Apply additive database migrations before dependent deployments; retain rollback compatibility. Distinguish browser response mocks from real storage tests and remove synthetic records. Record source/deployment IDs, tests and operating instructions. No DNS or paid-service changes are implied by the plan.
